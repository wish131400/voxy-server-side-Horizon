# Voxy Server Side Horizon

VSS 的独立 Fabric 移植版本。服务端读取或生成真实区块列并同步给客户端；客户端可以使用 Java / Rust 预测远处地形、植被和结构，再交给 Voxy 的统一体素渲染流程。

本仓库基于 VSS 0.3.6 的 NeoForge 版本继续开发。原 Forge 1.20.1、NeoForge 1.21.1 项目独立维护；它们的安装包不能直接用于 Fabric。

源码构建保留上游 Java、着色器和依赖声明，只固定构建身份并选择对应 Fabric 目标；它们不等于上游正式发布。wu-bao 的发布包内提交与发布标签对应源码不同，water-fix 发布包没有有效提交标识，因此按实际文件摘要验收。固定依赖工具保留来源和完整校验值；兼容结论仅覆盖这些输入，不自动覆盖各分支后续提交。VSS 安装包不包含上述第三方模组。

1.20.1 的 mihile port.9 发布包使用 Java 17 字节码，m3t4f1v3 与 tkettela 固定源码构建使用 Java 21；VSS 自身的 1.20.1 服务端保持 Java 17。上述六种组合共用对应 Minecraft 版本的 VSS JAR，不需要为每个 Voxy 分支安装单独的 VSS 文件。

本轮适配显式 far 参数的投影接口、不同任务队列的完成回执与邻居平面读取，并避免 water-fix 的旧水面高度校正重复生效。tkettela 原生中间变量形式的模型缩进和液面高度也由该分支保留，VSS 不再叠加一次修正。tkettela 分支在 VSS 会话中由 VSS 负责真实列同步，停止该玩家的重复原生请求与发送；无 VSS 会话时保留原生传输。整列原生任务成功完成后再接管预测，包含真实空气；丢弃、失败、旧会话及旧时间戳的迟到回包不能获得完整列确认或覆盖较新快照。

tkettela 此固定提交还存在上游配置初始化顺序缺陷：新配置或 `preset=auto` 可在原生 `ServerLodConfig` 初始化时访问尚未赋值的 `PRESETS`。客户端的 Voxy 渲染和 VSS 传输可继续工作，但不能据此宣称该提交自带的原生 LOD 服务端已可用。本轮未修改第三方 JAR；VSS 专用服务器无需安装 Voxy，不依赖该配置。保留原生协议兼容入口与实际验证该上游服务端分别记录。

当前定位为候选移植版。编译、离线回归、真实依赖接口检查、GPU 合同和启动检查分别验收；标题画面初始化不代表实际游戏内地形和光影已经验收。实际游玩、长距离移动、传送、预测切换、重新进入世界及具体光影包的画面与帧时间仍需实机确认。

新增的 1.20.1 和 1.21.1 已完成生产编译、网络与模块回归、世界生成迁移、真实 Voxy / Iris 接口及 GPU 检查。两版专用服务器均完成启动、真实列预生成、缓存保存与正常退出；客户端完成标题初始化，并实际调用生产预测代码验证材质图集读取。1.20.1 的专用服务器使用 Java 17，配套社区 Voxy 的客户端使用 Java 21。测试中需显式启用的分配微基准、未提供的历史 Voxy 或可选世界生成模组输入，均单独记录为跳过。

本轮还同步了下午的 Voxy 根节点 / 遍历队列容量修复，并修复客户端世界生成快照缺少静态注册表、要塞首选生物群系标签未展开的问题。六个现代目标的完整原版植被和结构快照往返共 38 项针对回归通过；旧两版也使用实际网络注册表执行对应回归。植被与最终体素使用新的缓存身份，更新后会重新生成旧的空植被结果，已有原始地形采样仍可复用。

## 安装关系

- 服务端安装对应 Minecraft 版本的 Fabric Loader、Fabric API 和 VSS。专用服务器不需要 Voxy。
- 客户端安装对应版本的 Fabric Loader、Fabric API、VSS，以及 Voxy 要求的依赖。远景显示需要 Voxy。
- Mod Menu 为可选依赖，用于打开配置界面。
- 光影兼容按对应版本的 Iris / Voxy 实际接口验证，不以模组名称相同代替兼容检查。
- 服务端与客户端使用匹配的 VSS 协议。旧 Forge / NeoForge 的列体和世界生成格式不能与本移植版混用。
- 本轮世界生成快照修复需要联机服务端与客户端一起更新；单人游戏会随同一个 VSS JAR 更新两端。
- 八个 Minecraft 目标的协议和列缓存格式也分别隔离，升级目标时不要混用旧列缓存。
- 未列出的 Voxy 社区分支、世界生成模组、地图模组和光影包没有获得本矩阵的兼容结论，保留的可选适配入口不等于已完成实测。

## 保留的能力

- 服务端真实列读取、预生成、持久缓存、传输、取消与脏列更新。
- 客户端 Java / Rust 地形、生物群系、植被和结构预测，精细体素缓存及近处优先调度。
- 预测和真实数据共同接入 Voxy 构网、细化、遮挡与绘制；真实数据优先，预测不写入 Voxy 的真实持久缓存。
- 世界、维度与种子身份隔离，以及真实列捕获和预测交接。

JAR 内包含 Windows x64、Linux x64 / ARM64、macOS Intel / Apple Silicon 的 Rust 库。Linux 库以 glibc 2.28 为基线，macOS 库以 11.0 为基线；这些是原生库的构建要求，Minecraft、Java 和图形驱动仍有各自的系统要求。

## 构建

1.21.11 使用 Java 21；1.21.1 同样使用 Java 21，并显式指定目标：

```text
gradlew remapJar
gradlew remapJar -PmcTarget=1.21.1
```

1.20.1 的生产代码使用 Java 17。使用 Java 21 启动 Gradle，并安装 Java 17 工具链：

```text
gradlew remapJar -PmcTarget=1.20.1
```

26.x 使用 Java 25，并指定目标，例如：

```text
gradlew jar -PmcTarget=26.1.2
```

标准产物位于 `lib`，例如 `vss-0.3.6-fabric-1.21.11.jar`。文件名不追加临时修复后缀，构建标识和源码摘要写入 JAR 清单。

当前八目标候选包的构建标识为 `fabric-22ee25355222`，均已通过生产构建和包内源码、版本与原生库校验。`lib/SHA256SUMS.txt` 按目标列出各标准 JAR 和合包的校验值。

`lib/vss-0.3.6.zip` 按 Minecraft 版本分目录收纳构建，附带构建清单和源码摘要。该合包只包含本仓库的 Fabric 版本。

## 源码组织

- `src/main`：共享调度、网络、缓存、预测核心，以及 1.21.11 实现。
- `src/versions/mc120`：1.20.1 的网络通道、世界生成与渲染接口适配。
- `src/versions/mc121`：1.21.1 的世界生成、载荷与渲染接口适配。
- `src/versions/mc26`：26.1 系列及后续版本的差异实现。
- `src/versions/mc262`：26.2 开始的差异实现。
- `src/versions/mc263`：26.3 的世界生成与渲染差异实现。
- `tools/rust/vss-native-core`：共用的 Rust 原生计算与 JNI 接口。

构建时，同一路径的类只选择一个实现，优先使用更具体的版本目录。不能用扩大元数据版本范围的方式跳过接口验证。
