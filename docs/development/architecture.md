# Fabric 架构与版本边界

[文档目录](../README.md)

共享核心负责请求、缓存、调度、预测和 Rust 桥接；加载器与 Minecraft 差异集中在平台入口和版本目录。同名类只选择一个实现，具体目录见 [构建与源码组织](build.md#源码组织)。

| 部分 | 职责与边界 |
| --- | --- |
| 平台与网络 | Fabric 入口、事件、命令、载荷与服务端／客户端会话；专服入口不加载客户端类 |
| 真实列 | 服务端读取、生成、缓存、传输、取消、版本与脏列更新；客户端交付 Voxy 或受支持消费者 |
| 世界生成快照 | 捕获实际服务端注册表、标签和模组路由；客户端在隔离上下文重建 |
| 预测 | Rust / Java 计算地形、群系、植被和结构；管理 CPU 数据、任务与缓存 |
| Voxy 接入 | 合成真实数据与不可变预测体素；Voxy 负责构网、细化、遮挡、上传与绘制 |
| 生命周期 | 世界、维度、种子、epoch 与版本校验；旧会话任务不得发布到新世界 |

真实数据优先，预测不写入 Voxy 的真实持久缓存。共享业务修改保留完整功能；可选适配必须针对具体输入验证，不能用空实现或通用回退掩盖缺失的必需路由。后台计算使用安全快照，世界和 GPU 资源由各自线程及唯一所有者管理。

1.21.11、1.20.1、1.21.1 与 26.x 分别维护实际 API、网络和列格式边界，不能直接共用其他目标的安装包。Fabric 的世界生成修复范围见 [适配说明](../compatibility/worldgen.md)，其结论不自动套用到 Forge / NeoForge。

旧阶段设计与实施分工保存在 [原始移植计划](../history/fabric-port-plan.md)，当前任务入口是 [PLAN](../../PLAN.md)。
