# 世界生成分阶段执行

预测使用服务端发送的种子、注册表、标签、维度边界、生成器参数，以及已有的框架初始化快照。Java 对象在客户端重建；运行时缓存、规则上下文、密度编译工作区和临时区块属于本次会话或工作线程，不作为 Java 堆快照发送给 Rust。

## 选择执行器

| 输入或行为 | 执行方式 |
| --- | --- |
| 已支持的密度图及群系源 | 保持 Rust 批量地形计算 |
| 未识别的密度函数或群系源 codec | 使用安装模组提供的 Java 实现，不把未知节点当成常量或原版节点 |
| 密度图可用，但地表规则包含未知 codec | Rust 计算地形，原 Java 规则计算地表；植被通过修正后的 Java 地表放置 |
| 噪声生成器子类重写独立列、噪声填充或独立地表入口 | 校验 codec 能重建同一实现，再在隔离临时区块中执行原方法 |
| 生成阶段要求真实 WorldGenRegion、完整生成邻域或服务端私有状态 | 使用已有显式后端或服务端真实 LOD；不创建不完整的伪 ServerLevel |
| 其他类型的自定义生成器 | 保留 TerrainSnapshot / PredictionLodSource 扩展入口与真实 LOD 路径 |

`GeneratorStageCapabilities` 按被覆盖的输出方法签名分类，不使用模组名称白名单，也不因为重写调试信息或 codec 方法而拒绝整个维度。它不能自动发现所有注入原版类内部的 Mixin；这些行为仍需要框架初始化快照、明确的投影或原阶段适配。

`PredictionExecutionPlan` 分开判定地形与地表。Rust 的专用输入是原输入的副本；未知地表规则只在这份副本中替换为默认材料，原规则对象继续由 Java 执行。显示采样、精确装饰代理、批量网格、任意显示点与洞穴地表均进入修正路径。不能继续使用原生植被代理时，转交既有 Java 特征执行流程。

## 上下文及失败处理

`PredictionOriginalStages` 持有重建生成器、RandomState、注册表和有界的临时区块缓存。未知生成器可能持有可变内部状态，因此该实例的原生成调用串行执行；其他维度及 Rust 工作任务保持原有调度。

地形完成后，地表在独立的临时区块副本上执行。地表失败时丢弃其写入，保留完成的地形，不反复重算同一区块。原地形阶段本身缺少必要运行时上下文时，记录不可用原因并停止重复调用，继续依赖真实 LOD。关闭会话会清理临时区块、编译资源及生成器拥有的资源。

早期缓存和最终采样器使用相同的阶段语义标识。原生成阶段、混合地表和已注册函数替换的版本均参与缓存隔离，避免加载旧算法生成的最终结果。

## 局部函数优化

`DensityFunctionReplacements` 允许按精确 Java 类注册经过等价验证的函数替换，带稳定 ID 和算法修订号。工厂得到当前种子、注册表和已初始化 RandomState；未知类继续执行原实现。现有密度编译与批量 Rust 入口保留，不在逐点调用中增加 JNI 往返。

双精度版本在密度编译之前应用替换；带外部运行时所有权的图保留原根。26.3 在 FP32 图上通过 `rewriteChildren` 应用替换，然后继续使用 Minecraft 编译器及每工作线程独立的 `SamplerContext`，不转换回旧版双精度图。替换失败会保留原 Java 函数。新增替换必须保证输出和状态语义等价，不能凭函数名字推断纯度。

26.3 将噪声与地表合并到需要真实区域的入口。本次支持其独立原列实现；任意自定义合并阶段不属于客户端隔离执行的覆盖范围。

## 验证边界

离线回归覆盖未知原生成方法、临时区块复用、地表失败回滚、液体与空列、关闭后的取消、阶段输入隔离、未知密度节点、精确类替换及失败回退。编译和离线回归不能证明任意第三方模组的画面一致，也不能替代实际整合包的加载速度测量。
