# 完整地表细化的区块复用与分批发布

构建标识：`chunk-refinement-20261115-r3`，模组版本仍为 `0.3.7`。适用于 NeoForge 1.21.1、Forge 1.20.1，以及 Fabric 1.20.1、1.21.1、1.21.11、26.1、26.1.1、26.1.2、26.2、26.3。

上一构建在使用运行时 Java 地表钩子时，完整细化需要为每个区块独立计算 256 根原生噪声列，重复建立噪声上下文和访问插值单元。大的采样网格还会一直占用任务，直到所有钩子完成才发布。本次使用 Rust 已有的整区块填充算法，共享噪声单元与含水层上下文，再交给原来的 Java 地表钩子；群系与地表兼容行为继续保留。

完整细化改为按区块分批执行。每批至少完成一个区块，在区块之间检查 32 ms 时间预算和最多 8 个区块的数量预算，完成后发布已有进度，再由调度器续算。这是区块之间的协作让出，单个区块或模组钩子本身可能超过 32 ms。基础覆盖、已完成细化和真实区块采样一起保留，下一批复用已完成的柱体；衔接边缘的完整采样网格也随进度保留，避免裁剪后反复计算。

未完成的地表仍参与后续调度，不能被判定为植被就绪、用于完整父级归并或写成最终磁盘缓存。保留进度的数组、采样对象和柱体占用纳入内存统计。旧外置 ABI 6 原生库缺少新增入口时，仍可回退到原来的列批处理入口。

Fabric 26.3 加载 Terrestria 8.2.0-alpha.1 / Biolith 3.8.0-beta.2 的隔离服务端夹具中，同一进程、相同 8 个区块：整区块原始填充累计约 257.51 ms，独立列填充约 897.84 ms，该计算阶段约快 3.49 倍；786,432 个状态编号逐项比较无差异。包含 Java 地表钩子的另一组 16 点完整路径耗时约 1070.49 ms，重复读取没有重新执行钩子。这些结果说明了计算阶段的收益，不代表实际游戏总加载速度或帧数具有相同倍数。

三套原生库另用主世界、下界和末地夹具分别检查 18 个区块，每套比较 983,040 个状态编号，均无差异，同时检查缓冲区与坐标边界。Windows x86_64 执行了原生验证；Linux x86_64 / aarch64、macOS x86_64 / aarch64 已交叉编译并检查架构、导出、依赖和校验值，未在这些平台执行。

各加载器的回归覆盖分批续算、负坐标区块归组、衔接边缘保留、完整质量判断、真实采样优先权、父级归并和磁盘写入限制。实际客户端的移动、传送和长时间细化表现仍需安装新构建后验证。
