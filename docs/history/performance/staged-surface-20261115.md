# 运行时地表兼容的分阶段加载

构建标识：`staged-surface-20261115-r2`，模组版本仍为 `0.3.7`。

保留运行时群系上下文、Rust 密度计算和完整 Java 地表钩子。首次覆盖使用稀疏的基础地形采样，后续任务再执行完整地表阶段；基础结果带有独立的未完成标记，网格达到目标精度后仍会继续调度。植被完成状态和最终磁盘缓存不能消费未完成结果，已完成结果也不能被迟到的基础结果覆盖。

完整地表阶段使用原生基础方块列作为输入，省去此前的原生材料列处理；同一区块的请求连续处理，复用完整钩子输出和工作线程的原生缓冲区。下界、末地等需要完整占用信息的维度，在基础阶段仍保留完整柱体采样。来自真实区块的采样保留优先权。

Fabric 26.3 的 Terrestria 8.2.0-alpha.1 / Biolith 3.8.0-beta.2 隔离服务端夹具中，同一组 16 个、间隔 64 格的采样点，基础覆盖耗时约 77.38 ms，未触发完整钩子；完整地表细化耗时约 2407.76 ms，执行 16 个区块的钩子，再次读取没有重复计算。该对比验证了基础覆盖可以先发布，不代表整个世界的加载速度提升相同倍数，也不是帧数测试。

完整细化仍需支付模组钩子的实际计算成本。依赖服务端世界状态的特殊地形继续需要真实 LOD 兜底，基础显示不能保证还原这类几何变化。缓存命名空间已升级，旧兼容路径的结果保留在磁盘但不会被误认为新路径的完成结果。

验证范围包括：未完成质量的生命周期、目标精度下的调度、原生需求队列、磁盘写入限制、真实采样优先权、负坐标区块归组、取消、Terrestria 群系一致性和完整地表钩子。实际客户端画面与传送、移动时的吞吐量仍需安装新包后观察。
