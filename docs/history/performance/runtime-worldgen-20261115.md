# 运行时群系、地表与预测开销修正

本轮保留 Rust 密度计算，为通过 Mixin 注入原版类的群系和地表行为恢复独立 Java 上下文。

- 服务端快照包含 Biolith 已完成的群系参数、替换区间、子群系条件和噪声尺度；客户端创建会话对象，不重置框架全局服务端状态。可能群系集合同时包含替换和子群系的输出。
- 地形、群系、材质颜色、地表和 Java 装饰读取同一份群系路由。无法使用原生群系入口时，回到已恢复的 Java 上下文。
- 识别原版地表类上的外部 Mixin，在 Rust 地形上执行完整地表阶段。相同区块合并请求，不同区块可并行；保留最多 64 个区块、16 MiB 的不可变竖向结果，不长期保存临时区块。
- 钩子缺少真实世界状态而失败时，丢弃该块的部分写入，恢复地形并执行可用地表规则。失败按块处理和缓存，其他区块继续完整地表阶段。此回退不等于完全还原该钩子的特殊地形。
- 细化队列保留已接纳的同优先级任务；只有新目标至少近半个 tile 时才替换。更高优先级仍及时抢占，不减少细化精度或距离。
- 缓存写盘同时计算内容哈希，避免预测线程为判重先完整序列化、写盘时再次编码。相同内容和失效检查继续生效。
- Java 放置计划按对象身份复用，避免遍历整张 Feature 图计算结构哈希；不更改随机数顺序或不支持规则的原执行方式。
- 真实数据与预测数据合成时，连续竖向覆盖查询复用同一个区段条目；已保存覆盖按节点成批查询，保留真实空气的覆盖语义和存档隔离。

## 验证与边界

真实 Fabric 26.3、Terrestria 8.2.0-alpha.1、Biolith 3.8.0-beta.2：12,000 点群系路由比较，包含 1,453 个 Terrestria 群系点，未发现差异；8 个完整地表区块在服务端上下文中执行无异常。经过实际 VSS 压缩快照、注册表恢复和 Rust/Java 混合入口的 256 个群系点与原路由一致，地表及内部体素查询一致。

移除 Terrestria 服务端世界引用的独立客户端模拟中，有一个海岛区块进入规则回退，重复访问复用已完成结果。Terrestria 海岛钩子直接读取服务端世界，因此远程客户端仍不能保证完全复现该钩子新增的海岛形状；需要已有真实区块 LOD 保证一致。该边界不影响其他可隔离阶段继续运行。

本轮针对正确性、任务更替与重复计算完成验证。未进行换包后的同路线帧率、长期移动或整合包画面测量，不宣称固定 FPS 增幅。其他维护版本采用相同架构，第三方模组的真实运行验证仅针对上述 26.3 发行包。
