运行时确认 CPU 支持 SSE4.1 后才进入专用函数，其他 x86 CPU 保留通用路径。此处使用标量精确取整指令，未实现多列 SIMD；不启用 FMA 或 fast-math，不改变 FP64 坐标、FP32/FP64 运算顺序、随机序列或地形配置。

Forge 与 NeoForge 的全部 39 个 Rust 编译输入逐文件一致，包括 Cargo 配置、锁文件与新回归源码，所以只构建一次旧版核心并把同一组五平台产物安装到两个项目。没有用 Fabric 的整个 Rust 目录覆盖旧版实现。

## 26.3 角点缓存

每个实际插值器拥有一个惰性分配的数组槽，求值体积总格点数最多 4,096。一个工作区内所有数组内容累计上限为 1 MiB；数组元数据和实际保留容量均计入工作区内存统计。此上限针对新增的数组内容，不代表整个工作区或原有哈希缓存的总大小。

改变求值体积时清除值并复用容量；切换区块和结构密度时使其失效。递归返回后核对当前体积，避免写入被嵌套求值替换的槽。超尺寸、不对齐或数组预算用尽时继续使用原有哈希路径，不丢失查询。

范围判断同时匹配单元坐标和实际求值体积，避免把旧体积的八角值误作当前标量查询的空域证明。该修复已包含在本次原生库中。

Ryzen 7 7700、Windows x86_64、JDK 25。使用实际游戏版本导出的世界生成输入、固定群系与共用方块属性，16 个独立窗口、共 1,024 列；各对照在独立 JVM 中串行执行，七轮取中位数。每窗口相隔 4,096 格，下表查询点间距为 4，单位毫秒。

这些比例只衡量 CPU/JNI 地形显示计算，不包含 Java 植被、磁盘、调度、Voxy 发布或渲染，不能直接换算为 FPS 或整张远景补齐速度。

## 验证与边界

- Fabric：90 项 Rust 库检查通过，4 项外部输入／计时诊断保持忽略；15 项显示、2 项现代缓存／地表和 3 项旧噪声检查通过。
- 旧版核心：2 项通用与专用指令路径检查、3 项噪声参考和 10 项世界生成检查通过。两个主仓库编译输入、五库 SHA 完全一致。
- 现代噪声完成 60,432 次 SSE／通用逐位对照；旧噪声覆盖不同随机种子、坐标周期边界及混合噪声。
- 真实现代图的 70,800 次编译／未折叠递归对照中，参考工作区强制保留原哈希角点路径；另覆盖预算耗尽、容量复用、嵌套体积、结构密度变化、重置和内存记账。
- 五平台产物交叉构建，包审查核对 JNI 导出、架构、Linux glibc 2.28 上限、macOS 11.0 下限与 ARM macOS 签名。
- Linux/macOS 未做本轮运行验证；ARM 未做真机计时。ARM64 原先已能生成直接取整指令，本轮没有新增 NEON 批量实现，也不承诺与 Windows x86_64 相同的比例收益。
- 最终 Windows 库另行执行 Vulkan 正确性检查，结果记入原生构建元信息；本轮没有实际游戏画面和 FPS 验证。
