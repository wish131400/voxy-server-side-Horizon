# 26.3 密度路径性能审查（2026-10-31）

[历史目录](README.md) · [已发布的上一轮优化](refinement-grid-20261031.md)

本次审查确认了两个末地优化缺口，以及主世界的剩余成本。下文记录实施前基于 `20261031-refinement-grid` 的诊断和隔离候选；后续正式实现与验证见[密度与地表高度搜索优化](density-surface-optimization-20261031.md)，不要把本页候选状态当成当前发布状态。

## 测量方法

使用真实版本的世界生成快照，固定平原群系和共用方块属性，在同一机器串行执行。吞吐测试调用未启用 profiling 的 JNI 库，每组独立 JVM，16 个相距 4,096 格的窗口、每窗口 64 点，共 1,024 列，九轮取中位数。创建世界不计入列查询耗时。修改前后比较完整十字段输出校验值。

阶段计时与事件计数分别构建，均不用于声称正式库吞吐。阶段版本关闭 `Graph::compute` 中五处细粒度 profiling 开关，避免每个节点启动计时器；事件版本单独数缓存、角点、噪声及区间调用。噪声耗时再次单独测量，关闭节点和 octave 计数，仅保留阶段与实际噪声调用的计时器。

现有 `profiling` 的噪声分类仅覆盖旧节点，未覆盖 `Node::Modern`，且在每个实际求值节点创建 `Instant`。直接用它比较两条图执行器会失真。新增的可移植 `display_audit` 示例提供相同的坐标、输出校验和 JSON 阶段记录；标准 profiling 模式仍有上述开销，必须与未插桩吞吐分开解读。`display_total` 与 `adaptive` 包含递归子查询，不能和各阶段简单相加；本报告使用互不重叠的记录阶段或外层实际耗时。

这不是同画面 FPS 对照，也没有测 Java 植被、磁盘恢复、GPU 计算、任务等待或 Voxy 发布。跨版本生成图和部分输出不同；收益百分比均来自同版本、同输入的修改前后对照。

## 1. 末地的有限范围缺失使两角点路径失效

位置：`tools/rust/vss-native-core/src/density/modern_range.rs` 的 `global`，以及 `density/modern.rs` 的 `Interpolated` 分支。

26.3 的末地岛屿值由两条分支取最大值：原点距离构成的中央岛分支，以及 `end_outer_islands` 外岛分支。范围分析同时缺少 `Distance` 和 `End`，因此整条输入链保持无限范围。即使查询正好落在 X/Z 插值格点，也不能证明其余六个零权重角点不会引入 NaN，必须计算八个角点。

先前仅补外岛范围没有收益，是因为中央岛的距离分支仍然未知。需要两个节点的有限范围一起传播。隔离候选为外岛记录 `[-0.84375, 0.5625]`；对包装后的 i32 坐标差，距离度量均有限，平方欧氏距离使用保守上界 `2e19`，其余使用 `1e10`。它们覆盖全 i32 输入，且没有修改噪声、插值算术和高度结果。

| 26.3 末地间距 | 当前库 ms | 仅补两个范围 ms | 耗时下降 |
| --- | ---: | ---: | ---: |
| 1 | 4.510 | 4.363 | 3.3% |
| 4 | 37.458 | 36.545 | 2.4% |
| 16 | 189.053 | 50.476 | 73.3% |
| 64 | 201.170 | 51.455 | 74.4% |

完整输出一致。另一组负坐标、种子 -917 的独立验证也输出一致；间距 16、64 分别从约 140.8、142.6 ms 降至 37.6、40.0 ms。这组只有两轮，作为一致性与方向复核，不能替代上表九轮结果。

候选通过两项定向单元检查：四种距离度量、坐标整数边界与包装减法的范围包围；实际末地插值输入的有限范围。现代点缓存逐位对照和地表搜索与逐块下降扫描对照也通过。后者补充了正负远坐标，并保留不同网格、薄层和重复访问覆盖。

## 2. 末地中层复用仍按旧的 4×4 逻辑尺寸判断

位置：`Terrain::from_document` 为现代图保留 `cell_width = 4`；`backend/display.rs` 的 `reuse_density_cells` 判断与 `Job::search_density_surface` 的横向键都使用这一尺寸。

末地实际插值为 8×8×4。间距 4 的两个相邻点共享实际插值单元，却属于两个逻辑 4×4 单元，因而无法启用同一单元的空域证明与搜索上限复用。计数中，旧版末地间距 4 有 1,242 次区间搜索；26.3 有 28,335 次，约 22.8 倍。混合噪声调用却基本相同，分别为 15,737 与 15,728 次，因此主要多付了搜索和查表成本。

在上节有限范围候选基础上，仅为末地诊断把逻辑宽度对齐为 8，结果如下：

| 26.3 末地间距 | 当前库 ms | 仅补范围 ms | 再对齐横向尺寸 ms |
| --- | ---: | ---: | ---: |
| 1 | 4.602 | 4.280 | 3.760 |
| 4 | 38.435 | 35.753 | 29.614 |
| 16 | 190.027 | 51.451 | 48.547 |
| 64 | 200.886 | 52.793 | 52.395 |

同轮完整输出一致。间距 4 相对仅补范围再下降约 17.2%，相对当前库下降约 23.0%。

该宽度改动仅用于验证原因，不能原样进入正式库：主世界、嵌套插值、模组网格和精确生成仍需要原有逻辑尺寸。正式方案应单独计算最终密度依赖的地表搜索横向尺寸，并让复用键和整单元证明使用同一个范围；不能直接全局把现代 `cell_width` 改成 8。

## 3. 主世界仍有更多区间工作和更贵的单次噪声计算

主世界间距 4 的阶段诊断中，26.2 的密度边界为约 54.3 ms、材质为 13.7 ms；26.3 为约 83.7 ms 和 4.3 ms。颜色、分组和工作区准备均非主要差距。这两组主世界样本的完整列回退次数都是零。

相同 1,024 列的事件计数如下。此处跨版本输入不同，用于定位所做的工作，不代表数值输出必须一致。

| 主世界间距 4 | 26.2 | 26.3 |
| --- | ---: | ---: |
| 区间搜索 | 35,864 | 35,881 |
| 密度子图范围判断 | 50,834 | 192,838 |
| 普通噪声调用 | 204,158 | 194,424 |
| 混合噪声调用 | 26,655 | 25,336 |

26.3 的范围判断约为 3.8 倍，噪声调用反而减少。旧 `SurfacePlan` 专门编译了 min、squeeze 和正比例缩放的符号路径；现代图仍由通用范围分析遍历 squeeze、min、beardifier 等包装。隔离候选为有限 min、squeeze 和零 beardifier 增加符号路径，完整输出一致，但主世界间距 4 仅从 93.67 ms 降至 90.77 ms，约 3.1%；间距 16、64 约 1.9%、3.3%。它是可优化的额外开销，尚不能解释或解决全部差距。

另外，现代两角点分支没有旧路径的独立端点缓存，主世界间距 4 发生约 84,588 次两角点加载路径。独立增加按单元、体积区分的端点缓存后，间距 4 从 93.58 ms 到 90.77 ms，约 3.0%；间距 16 基本不变。不能把大量缓存命中次数直接换算成巨大实际收益。

单独计时实际噪声调用、关闭节点及 octave 计数后，按调用次数折算：主世界间距 4 的普通噪声约由每次 111 ns 到 138 ns，混合噪声约由 905 ns 到 1,163 ns。末地间距 16 的混合噪声调用基本相同，26.2 为 102,972 次、约 89.9 ms；26.3 为 102,960 次、约 116.5 ms，单次约增加三成。计时器有固定开销，这些是诊断估计，不是独立内核吞吐承诺。

26.3 虽使用 FP32 梯度和累加，坐标与周期折返仍为 FP64，还需保持标量和体积路径各自的运算顺序。FP32 不会自动使当前标量实现更快。下一步主世界应针对 `noise/modern.rs` 的实际噪声核、体积插值上下文和批量执行做专项基准，保留逐位输出；扩大线程数或削减地形计算不能修复上述实现差距。

## 实施顺序与状态

1. 优先正式补齐末地两个节点的有限范围，并增加可保留的边界及实际路径回归。
2. 单独设计地表搜索的横向网格尺寸，不修改精确生成的逻辑工作区尺寸。
3. 主世界先独立优化噪声核和批量执行；符号路径与端点缓存只按已测得的小收益评估。

本次审查阶段仅新增示例和记录，隔离候选当时未发布，也没有执行游戏内 FPS、GPU 路径或多平台原生库验证。后续实施、五平台构建和 GPU 验证见[正式优化记录](density-surface-optimization-20261031.md)。完整输入、事件数据、阶段数据和各候选源码保留在忽略目录。
