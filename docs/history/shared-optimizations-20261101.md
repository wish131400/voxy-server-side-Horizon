# Fabric 公共查询与密度依赖复用（2026-11-01）

构建 `20261101-shared-fabric`，VSS 0.3.7。对应 NeoForge/Forge 的装饰公共查询、材料段高度与密度依赖优化，按 Fabric 八目标的实际代码适配。

## 应用范围

- Java 精确地表查询使用对齐 4×4 页，仅提交共享缓存缺项；原始地表记录不提前查询群系，完整采样与发布时继续补齐原生群系身份。已补齐的记录不能被并发中的旧原始页覆盖。
- 装饰仅求方块和高度时保留原始记录；未修改的表面按材料段求高度，仍使用完整方块状态和 Heightmap 谓词。有覆盖写入、内部体积和 Java 地形保持原路径。磁盘恢复、回滚及版本回绕均登记逐柱变化，版本数组延后到首次实际写入分配。
- 显示与精确缓存分别遵守自己的生成策略，避免装饰预取改变下一次显示地形和植被高度；增加装饰缓存设置版本以失效旧结果，原始地形缓存保持兼容。
- Rust 世界初始化时分析固定 SurfaceRules，按需计算依赖坐标的深度。量化气候参数工作区和原生 Feature 的 Raw 工作区复用，不跨调用缓存带顺序状态的群系答案。
- FP64 精确路径使用紧凑算术计划和世界拥有的插值输入租借表；保留浮点运算次序、短路、负零和缓存语义。单表 4 MiB、每世界最多 16 MiB、进程表载荷最多 64 MiB；停放和重定位归还，取消及图重建关闭旧池。
- Fabric 的 FP32、Vulkan、原生群系查询及 Java 特征统计保留。FP64 的角点身份不用于 26.3 独立插值体积。

## 性能取舍

移植前核对已有实现，保留 Fabric 自身的快速放置执行器和树模型。未采用命中很少、未证明整体收益的主动候选裁剪。

整套旧密度优化直接用于显示查询时，本机冷显示查询出现约 3%–9% 的额外耗时。隔离比较共享表、算术计划、局部角点数组和处理顺序后，最终仅在精确路径启用依赖复用，显示路径使用编译期分开的简单求值器，并保留原坐标角点表。未发布实验变体。

最终 DLL 数据及验证结果见后续表格。原生查询计时不包含 Java 完整装饰、磁盘、调度、GPU、Voxy 发布或渲染，不能换算为游戏 FPS；NeoForge 约 12.5% 的完整生成收益不视作 Fabric 实测收益。

## 正式原生库对照

Windows x86_64；同一台机器、实际版本导出的主世界输入，种子 42、坐标从 (100000,100000) 开始，16 批各 64 柱。每个 DLL 在独立 JVM 预热后运行七轮，取冷查询中位数；构建、测试与计时串行执行。1.21.1 和 26.3 另在末尾重跑旧 DLL，下表两者采用前后旧库中位数的均值作对照，其余采用单组旧库。所有十字段输出摘要与旧库一致。

| 目标 | 精确地表间距 4，旧 ms | 新 ms | 耗时减少 |
| --- | ---: | ---: | ---: |
| 1.20.1 | 129.641 | 123.997 | 4.35% |
| 1.21.1 | 129.511 | 125.855 | 2.82% |
| 1.21.11 | 123.624 | 116.981 | 5.37% |
| 26.1 | 123.554 | 116.074 | 6.05% |
| 26.1.1 | 123.057 | 116.662 | 5.20% |
| 26.1.2 | 124.072 | 116.092 | 6.43% |
| 26.2 | 124.856 | 116.370 | 6.80% |
| 26.3 | 128.787 | 126.574 | 1.72% |

26.3 精确地表间距 1 为 32.439 → 30.018 ms，减少 7.46%；它来自公共规则与工作区等优化，未使用 FP64 共享角点。旧版密集间距 1 的变化较小，1.21.1 经过尾部控制后约为持平，不能把间距 4 的收益推广到每种访问密度。

显示查询没有稳定的整体提速结论。最终八目标的间距 1/4 组多数落在约 ±3% 的变化内，26.2 间距 1 单组增加约 3.99%；26.3 有尾部控制的间距 1 增加约 2.96%、间距 4 近似持平。它们每批总计约 8–45 ms/1024 柱。初版持续增加 3%–9% 的显示路径没有采用；仍需真实游戏长时间采样确认调度与加载体验。没有用测试中的最好一组结果宣称显示或 FPS 加速。

原始正式矩阵位于本机构建归档的 `final/`，对照输入和库均记录 SHA；这些采样文件不随源码提交。

## 验证

- Rust 最终源码的九组专项合计 156 项通过、零失败，4 项既有外部诊断保持忽略。覆盖算术顺序、共享表生命周期、显示路径隔离、地表规则、新旧世界生成、材质与植被。
- Java 六个独立适配目标合计 241 项通过、零失败或跳过：1.20.1、1.21.1、1.21.11、26.1、26.2 各 40 项，26.3 为 41 项。覆盖材料段高度与逐块高度对照、首次写入、恢复、回滚、取消、原始页延迟补群系和并发缓存不降级；26.1.1、26.1.2 复用 26.1 适配，并分别构建交付。
- 26.3 使用最终资源目录的 Windows DLL，在 RTX 4070 Ti SUPER 上执行五项 Vulkan 专项，全部通过。覆盖原版密度与显示、已支持的模组节点、嵌套体积和不支持运算的 CPU 回退。
- 五个平台原生库完成交叉构建；Linux、macOS 和 ARM 未执行目标硬件运行及性能测试。未进行完整 Fabric Java 装饰或实际游戏 FPS 对照。
- 八个目标的标准 JAR 均完成构建与包内核对，构建期间生产和原生源码摘要保持一致。五个平台原生库均核对 48 个 JNI 导出、架构和资源字节；Linux 的 GLIBC 依赖不高于 2.28，macOS 最低目标为 11.0，ARM macOS 的临时签名通过页哈希核对。标准 JAR 与 `vss-0.3.7.zip` 发布到本仓库 `lib` 根目录，构建标识为 `20261101-shared-fabric`。

26.3 的测试输入使用实际新版材质规则、方块状态编码与 FP32 密度编码；中断恢复测试按首个窗口完成判定，避免依赖 CPU/GPU 分支的检查次数。
