# Rust 底层优化隔离审查（2026-10-31）

[历史目录](README.md) · [上轮地表符号计划](modern-sign-20261031.md)

后续落地见[密度求值特化与跨仓库同步](density-specialization-20261031.md)。本文保留隔离研究时点的状态和数据；正式库收益、交付与旧版内核同步以落地记录为准。

本轮检查机器代码、内存布局、循环指令并行和编译器反馈优化。基线为已发布的 `20261031-modern-sign`，范围是独立 Fabric 仓库的 Rust 核心。所有候选在忽略的 `external/performance/20261031-low-level/` 中构建和验证，尚未合入生产源码或替换正式原生库、JAR。

## 最有价值的候选：按密度格式编译期特化

目前 `Graph::compute` 同时包含旧版双精度和 26.3 单精度节点的调度、缓存及计算分支。图在构造完成后密度格式不再改变，但通用递归仍携带两种格式的分支和状态处理。

候选增加 `compute_typed<const MODERN: bool>`，为两种格式分别生成机器代码。公共入口依据图格式调用对应版本；旧版直接递归旧版实例，现代节点直接调用现代实例。缓存键、结构密度、浮点精度、加法顺序及插值顺序都沿用基线。格式由图构造器决定，候选没有增加运行设置、线程或降低采样质量。

在本机 release 汇编中，公共求值函数原来的静态栈分配为 600 字节；特化后，现代调度实例为 104 字节、旧版为 568 字节。现代节点自己的计算函数仍存在，104 字节不代表一次完整密度查询的全部栈用量，也不代表整个游戏的内存降幅。未采集硬件缓存或分支预测计数，不能据此宣称具体的缓存缺失率下降。

## 其他候选与取舍

| 底层方法 | 隔离实现与结果 | 判断 |
| --- | --- | --- |
| 缓存有效位图 | 将 `Vec<Option<f32>>` 改为 `Vec<f32>` 加 `Vec<u64>`；4,096 点的数据区由 32,768 降至 16,896 字节。切换体积只重置有效位，保留浮点原始位模式。当前相同 1 MiB 总预算下，整批耗时没有稳定改善，部分缓存组间距 4 首轮慢约 4%。每个缓存对象还会多一个 Vec 元数据。 | 可以继续作为缓存空间优化，不能称为已确认的加载提速；未采用。 |
| 噪声 octave 两层展开 | 提前计算两个独立层，再按原来的顺序累加，不使用 FMA 或 fast-math。多数输入波动约 0%–3%，也出现小幅退步。 | 没有足够稳定的增益，未采用。 |
| 拆分大型插值分支 | 原现代节点栈分配 776 字节；拆出插值后，编译器将现代节点内联进公共求值器，公共栈反而由 600 涨到 744 字节。26.3 首轮提速约 7%–9%，旧版倒退约 4%–11%。 | 单独拆函数不适合通用发布，未采用。 |
| 拆分并限制内联 | 保留现代节点函数边界后，公共栈恢复 600 字节，现代节点降到 504 字节；但 26.3 的大部分速度收益也消失。与格式特化叠加也没有一致的额外收益。 | 减小静态栈不能单独证明提速，未采用。 |
| PGO | 插桩采集三维度、新旧版本和部分缓存的运行频率，合并后重新优化。只合并 7 份运行时 DLL profile，排除构建阶段 proc-macro 的 profile；训练种子 42、坐标与验证集不同。干净 profile 的确认组里，26.3 主世界耗时下降约 6%–9%、下界约 9%–12%、末地约 5%–7%。旧版 1.21.1 / 26.2 中远间距反而慢约 8%–12%；提高旧版训练权重后仍有回退。 | 26.3 专用构建值得继续研究，当前不适合全部版本共用，也未验证跨平台发布流程。 |

优先采用的方向是密度格式编译期特化。PGO 可在此后重新评估，需要实际模组图、植被及更完整的工作负载覆盖。缓存位图的价值主要在单个缓存的数据布局。继续增加 SIMD 宽度、全局强制 CPU 指令集或改变浮点计算规则不属于本轮已验证的增益。

## 数值回归与实验文件

- 隔离候选通过 128 项检查，4 项原有外部输入／计时诊断保持忽略，没有失败。包含 97 项库检查、15 项显示地形检查、现代地表／体积缓存检查、Lithostitched 26.3 Java 参考、旧版随机噪声和 10 项完整世界生成检查。
- 库检查中的 70,800 次原版三维度／Lithostitched 现代图对照，以及通用／SSE4.1／AVX2 噪声逐位检查继续通过。
- 确认组 30 个间距配置的完整十字段记录与正式库一致；新候选的 `specialized-regression.log` 保留详细回归结果。
- 本轮未做游戏画面、FPS、Vulkan、交叉平台构建或 ARM 真机验证；没有替换生产资源。

隔离候选为 `specialized/`，源码差异为 `specialized.patch`，机器代码为 `specialized.s`；确认组汇总为 `confirmed-summary.json`。`first-*`、`split-*`、`guard-*`、`typed-*` 与 `confirm-*` 保存原始配对记录。PGO 训练和合并信息单独记录；带插桩的训练耗时从未作为提速证据。

生产基线 Windows DLL 的 SHA256 为 `308cae87e4bc4c0d67d6c9a2637454f3b1933a9468ce0e701fe6e05bb04c2cdf`；特化实验 DLL 为 `221a1ca62a563aeafc85f81a69fc2945f82b24420ee0bf2965e1ecba8eb45860`。本轮开始与结束核对生产 Rust 源码摘要，没有发生生产源码或正式库变更。
