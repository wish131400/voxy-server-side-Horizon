# 缓存细化与现代插值搜索优化（2026-10-31）

[文档目录](../README.md) · [上一轮八版本对照](performance-matrix-20261031.md)

构建标识 `20261031-refinement-grid`，面向八个 Fabric 目标，版本号保持 0.3.7。

## 改动

- 部分缓存细化不再为投机插值重新计算仅在 Java 中保留的探测点。只有 Rust 显示缓存已经保存这些探测点时，才尝试自适应网格；否则直接计算缺失点。平坦地形的已缓存探测点仍可支持插值，薄层、山脊和不支持的规则继续使用原有采样。
- 26.3 的地表搜索按最终密度依赖的插值网格高度分段。末地的节点高度为 4，原通用搜索高度为 8；跨节点边界时无法证明整个区间，曾反复递归采样。新的分段不改逻辑区块尺寸、实际插值公式和体积上下文。其他无关根节点的网格不影响最终密度搜索。
- 26.3 在 GPU 未开启、未准备好或该间距未通过 GPU 收益判断时，直接消费既有 8×8 CPU 窗口，省去 GPU 专用坐标、映射和高度数组，以及重复的窗口恢复。启用后仍会触发异步初始化；提交前保留状态复核。
- 同步上一轮 26.2 `interval_select` 有限分支范围修复，恢复可跳过零权重角点的插值路径。任一结果分支没有有限范围时仍使用完整回退。

## 定向收益

修改前后使用相同 JDK 25、种子和真实版本世界生成输入，固定平原群系与共用方块属性。每组独立进程执行九轮，取中位耗时；完整十字段记录校验值一致。计时期间没有并行构建或其他本轮验证程序。

| 场景 | 工作量 | 修改前 ms | 修改后 ms | 耗时变化 |
| --- | --- | ---: | ---: | ---: |
| 26.2 主世界部分缓存，间距 1 | 16 窗口，每窗口缺 48 点 | 10.94 | 11.55 | 增加约 5.7% |
| 26.2 主世界部分缓存，间距 4 | 同上 | 59.46 | 53.15 | 下降约 10.6% |
| 26.3 主世界部分缓存，间距 1 | 同上 | 17.12 | 15.78 | 下降约 7.9% |
| 26.3 主世界部分缓存，间距 4 | 同上 | 92.92 | 75.51 | 下降约 18.7% |
| 26.3 末地，间距 1 | 1,024 冷列 | 13.26 | 4.43 | 下降约 66.6% |
| 26.3 末地，间距 4 | 1,024 冷列 | 36.43 | 37.01 | 增加约 1.6% |
| 26.3 末地，间距 16 | 1,024 冷列 | 180.58 | 187.79 | 增加约 4.0% |
| 26.3 末地，间距 64 | 1,024 冷列 | 191.26 | 190.93 | 基本持平 |

本轮主要收益出现在部分缓存的间距 4 细化，以及末地密集采样。26.2 间距 1 没有体现收益；末地稀疏查询也没有稳定提升。不能把单项最高收益用于描述所有 LOD 档位。26.3 主世界完整采样四档耗时变化约 1%–4%，不足以作为显著收益。

26.2 上一轮已验证的范围修复是单独的较大收益：间距 16 的主世界发布库由 241.14 ms 降至候选核心 79.05 ms。本轮“修改前”库已经包含该修复，不能再次把它算入上表收益。

## 验证范围

Rust 核心检查 80 项通过、4 项专门诊断跳过；显示回归 15 项通过；现代图逐位缓存对照与新增网格地表搜索检查各 1 项通过。新增用例覆盖实际末地、负坐标、同一体积内重复访问、薄层和不同尺寸嵌套插值。测试工作区遵循生产调用的单区块体积边界。

使用最终 Windows 资源库，对八版本三个维度执行普通采样四档和部分缓存网格两档，共 144 组修改前后完整输出校验，全部一致。这部分只作为一致性验证，运行期间的计时不用于上表。

五平台原生库完成交叉编译；Linux 与 macOS 没有本轮运行时验证。游戏内缓存恢复、植被、体素发布、GPU 与渲染竞争，以及 FPS 不在上述 CPU 计时范围内。26.3 的 Java 区域入口和最终库另行执行实际 Vulkan 回归；发布包校验核对构建标识、生产源码摘要、Rust 源码摘要、原生库校验值和关键调用。

最终五项 Vulkan 回归全部通过。打包检查还发现 1.21.11 与 26.2 的增量输出残留一个已删除源码的 FTB Essentials 类，触发注解兼容检查；两个目标清理构建输出后重新编译，并逐目标检查包内不存在无对应源码的 VSS 类。

完整性能数据、输入文档和运行日志留在忽略目录，仓库保留可移植基准工具与自包含回归用例。
