# UltraTerraForged 缓存锁修复（2026-11-06）

[当前兼容范围](../compatibility/ultraterraforged.md)

上一轮将 VSS 拥有的 UTF 内部批次放回预测线程时，UTF 的 `computeEntry` 仍在持有 `StampedBoundLongMap` 写锁期间调用生成器，因此完整瓦片计算也留在写锁内，缓存命中读取可能被阻塞。

本轮保留原来的待完成缓存条目和完整滤波依赖链，在 `provide`、`queue` 调用 `computeEntry` 时暂存内部批次，等原方法返回、写锁释放后再在预测调用线程执行。UTF 拥有的真实区块生成器仍使用原来的异步调度。三个实际 Fabric Mixin 配置入口均登记新钩子，成品门禁检查其调用与配置。

针对性测试使用 UTF 1.0.3 的实际 Fabric 1.21.1 和 26.3 发布文件，应用两个生产 Mixin，并只在真实批次体入口加入观察。它检查两条入口在批次开始时可取得缓存读锁、原待完成条目已经发布且尚未完成、执行线程仍为原预测线程、重复请求返回同一瓦片，并将地形的全部公开 primitive 字段与上游完整滤波结果逐项对照。

这轮仅执行上述两个目标的缓存锁行为和原批次调度检查，不重复上轮的全矩阵。两目标各 2 项，共 4 项全部通过，无跳过或失败；没有以离线检查代替游戏加载速度与画面验收。
